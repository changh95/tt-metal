Each new interval either overlaps the last merged one (its start is at or before the last end), in which case the last interval is extended, or it begins a new merged interval.

```python
from typing import List


def merge_intervals(intervals: List[List[int]]) -> List[List[int]]:
    """Merge overlapping or touching closed intervals and return them sorted by start."""
    if not intervals:
        return []
    ordered = sorted(intervals, key=lambda pair: pair[0])
    merged = [list(ordered[0])]
    for start, end in ordered[1:]:
        last = merged[-1]
        if start <= last[1]:
            last[1] = max(last[1], end)
        else:
            merged.append([start, end])
    return merged


if __name__ == "__main__":
    assert merge_intervals([]) == []
    assert merge_intervals([[1, 3], [2, 6], [8, 10], [15, 18]]) == [[1, 6], [8, 10], [15, 18]]
    assert merge_intervals([[1, 4], [4, 5]]) == [[1, 5]]
    assert merge_intervals([[5, 7], [1, 2], [2, 4]]) == [[1, 4], [5, 7]]
    assert merge_intervals([[1, 10], [2, 3], [4, 5]]) == [[1, 10]]
    print("all tests passed")
```

A few notes:
- Sorting dominates the cost, so the function runs in O(n log n) time and uses O(n) extra space for the result.
- `list(ordered[0])` and `[start, end]` create new lists, so the input intervals are never modified.
- Because the comparison is `start <= last[1]`, touching intervals such as `[1, 4]` and `[4, 5]` are merged. Use `<` instead if they should stay separate.<|endofturn|><|endoftext|>
